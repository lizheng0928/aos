Chapter 4 · Project, Skill & Work — Turn One-Time Wins Into a System

4.5 Work: Package Skills Into a Role

By this point, you've used Projects to manage ongoing work, installed a few Skills, and even created your own. Workbench is starting to feel good. But every time you start a new task, you still have to think "which Skills should I use this time?"

It's like having a toolbox with everything in it — but before every job, you have to pick the tools yourself. The fuller the toolbox, the more of a burden tool selection becomes.

Work solves that.

What Is Work?

One sentence: Work is a bundle of Skills, packaged for a specific role or a complete job.

You don't pick Skills one by one. You say "I'm doing Amazon operations today," select the corresponding Work, and all the Skills it contains load as a whole. The Agent has the full capability set for that job — but note: the Agent won't automatically call the Skills. You tell it what to do in the conversation.

Analogy:

ConceptReal-life analogyWhat it means
SkillA screwdriver, a hammerSingle tool, does one thing
WorkAn electrician's tool kitPacked with everything the role needs — pick it up and go
AgentA workerShows up empty-handed. Picks up a tool kit = becomes that trade

Not every worker needs to know which tools an electrician carries vs. a plumber. The tool kit is already packed. You just choose which trade to work as today.

Skill vs. Work

You might ask: I've installed some Skills, they load by default, available in every task. How is Work different from Skill?

The core difference is in how they load:

DimensionSkillWork
AnalogyYour personal everyday toolsA complete tool kit for a specific role
After installLoaded by default, available in every taskMust be specified in the task to load; Skills inside the Work aren't auto-called — you direct the Agent
Best forGeneral, cross-scenario capabilities (document summary, email draft)Role-specific or project-specific complete capability sets
Example"Translate this paragraph" → general translation Skill"Generate this week's Amazon operations report" → Amazon Ops Work (includes competitor monitoring + review analysis + weekly report template)

Simply put: Skill is a "everyday tool." Work is a "job tool kit."

For everyday general tasks, Skills are enough. But when you need to complete a full job — like generating a weekly Amazon competitor report or launching a new listing in three languages — you don't need one or two Skills. You need a coordinated set of capabilities. That's when Work is much more efficient than picking Skills one by one.

How to Use Work

Real Example: Amazon Operations Work

Let's make this concrete. Imagine your company is a fashion brand with an Amazon operations specialist. What does their day look like?

9:00 AM, open the laptop. Check if there were any negative reviews overnight. Then check if competitors changed prices. Then check which listing's ranking dropped — adjust keywords. Afternoon: write the new listing's title and bullet points — needs SEO optimization and multi-language. Finally, the boss asks "how's last week's ACoS?" — another hour gone.

This is Amazon operations: the work isn't hard, but it's incredibly fragmented, and everything is interconnected. Monitoring competitors, reading reviews, optimizing listings, checking ads, writing reports… each task needs a different capability, but they're not independent tasks — they're one complete operational chain.

With Skills, every new task means manually picking: competitor monitoring Skill, review analysis Skill, listing optimization Skill, keyword research Skill… and then explaining to the Agent how these Skills work together.

But packaged as an "Amazon Operations Work", it becomes: pick one Work, get started.

How are these Skills built?

The 6 Skills below aren't hypothetical. Each has a clear data source and implementation path. Some work now. Some need external data permissions confirmed first:

SkillData sourceImplementation path
Competitor monitoringApify Amazon Product ScraperCall Apify Actor to capture listing snapshots, write to table, diff against last snapshot
Review analysisApify Amazon Reviews ScraperCapture reviews → LLM for sentiment analysis and keyword clustering
Listing optimizationLLM generation + keyword research outputPure Skill logic — no external API needed. Keyword data from Keyword Research Skill
Keyword researchApify Auto-Suggest + Brand AnalyticsApify captures search box long-tail keywords; search volume needs Brand Analytics CSV export
Ad data analysisAmazon Advertising reportsImport CSV to Library first, Agent reads and analyzes; Advertising API Connector possible later
Operations weekly reportExisting data in the tableAggregate data written by the Skills above, assemble by weekly report template

Among these 6, competitor monitoring, review analysis, and the weekly report can be implemented directly with Apify API + LLM. Listing optimization is pure Skill logic. Keyword research and ad data analysis need Brand Analytics CSV or ad report import. Start with competitor monitoring and review analysis — clearest data sources, simplest logic. Get these two working first to validate the full chain.

Scenario Demo: A Complete Operations Chain — From Monitoring Competitors to the Weekly Report

Traditional approach: competitor monitoring in Helium 10, reviews one by one on Amazon backend, listing changes in Seller Central, ad data in Excel, weekly report on Friday night. Five tools, five switches, five fragments.

With "Amazon Operations Work":

Open Workbench, create a new task, select "Amazon Operations Work" from the + menu.

Sub-scenario A: Daily competitor + review check

text Today's Amazon operations check: - My listings: B0DXXXXXX (Women's knit cardigan), B0DYYYYYY (Men's jacket) - Competitors: 3 ASINs in the same category - Check: 1. Did any competitor change price overnight? What's the price gap with mine? 2. Did any competitor change their title/bullet points? List changes if any. 3. How many new reviews for me and competitors? Sentiment (positive/negative/neutral)? 4. What are the common issues in negative reviews? (size/fabric/logistics/other) - Output: Write to the "Daily Check" view in the table, one row per ASIN

The Agent calls:

  • Competitor Monitoring Skill → captures current listing state, diffs against last snapshot
  • Review Analysis Skill → pulls latest reviews, sentiment analysis, keyword clustering
  • Operations Weekly Report Skill → writes results to the table, structured

About 3 minutes later, you have a check table in the table: one row per ASIN, price changes, listing changes, new review count, sentiment breakdown, negative review keywords. All clear at a glance.

Sub-scenario B: New listing launch — one-click listing generation

New listing launch is one of the most fragmented tasks: the title needs keywords and readability, bullet points need features and specs, and backend search terms need filling.

text New listing generation: - Product: Women's cashmere scarf, ASIN pending - Product images in Library /2026-FW/Accessories/Scarves - Target markets: US + EU (English/German/Italian) - Input: - Product name: 100% Cashmere Scarf - Selling points: Reversible, lightweight warm, classic plaid, gift-ready packaging - Specs: 140cm × 35cm, 230g, 100% cashmere - Output: 1. Title (≤200 characters, with core keywords) 2. Bullet points (5, ≤500 characters each, features + specs) 3. Product description (≤2000 characters) 4. Backend search terms (≤250 characters) 5. English → German → Italian versions - Constraint: Keywords from real Keyword Research Skill data — don't fabricate - Acceptance: Title includes "cashmere scarf" and "women's." Each bullet point has one core selling point

The Agent calls:

  • Keyword Research Skill → pulls "cashmere scarf" and related keywords: search volume, competition, long-tail terms
  • Listing Optimization Skill → generates title, bullets, description, and search terms in each language based on keyword data and product info
  • Multi-language copy generation Skill → translates English to German and Italian, preserving SEO structure

You get a complete three-language listing set, ready to copy and paste into Amazon Seller Central.

Sub-scenario C: Friday weekly report — from 2 hours to 10 minutes

text Generate this week's Amazon operations weekly report: - Time range: Last Monday to this Sunday - Sections: 1. Sales overview: total revenue, units ordered, return rate (vs. last week) 2. Review dynamics: new review count, average star rating, Top 3 negative review reasons 3. Competitor changes: price adjustments, listing modifications, new launches 4. Ad performance: total spend, ACoS, conversion rate, Top 5 spend keywords 5. Next week focus: 3 action items based on the above data - Data sources: "Daily Check" table + ad reports + inventory table - Format: Write to "Weekly Report" view in the table, also output summary in conversation

The weekly report is a summary task. You tell the Agent to aggregate the week's data. The Agent reads from the table — the data written by the previous sessions' checks, ad reports, and review analysis — and assembles a standardized report using the Operations Weekly Report Skill. The prerequisite: each previous session wrote its data to the table.

💡 This is the core value of Work: the Amazon ops specialist's five fragmented tasks — monitoring competitors, reading reviews, writing listings, checking ads, producing weekly reports — no longer need five tools and five switches. Pick one Work. Five tasks in one conversation, strung together into a chain.

Three steps:

1. Find the right Work in Explore

Open Explore in the left sidebar. You'll see four tabs: App, Work, Skills, Connectors. Click Work, browse available tool kits.

Each Work card shows:

  • Who this Work is for (e.g. "Amazon Operations Specialist")
  • Which Skills are bundled inside
  • One sentence about what it does

2. Install the Work

Same as installing a Skill — click Add. But the difference: after installation, the Work's Skills aren't all loaded into every task immediately. They're "on standby," waiting for you to specify the Work in a specific task.

You can enable or disable individual Skills inside the Work in User Capability Management. Turn off what you don't need. Make sure the ones you need are on.

3. Use the Work in a task

Start a new task. Click the + menu next to the input box. Select the Work you want to use. All enabled Skills inside that Work load as a whole into the task's Agent context.

You don't pick individual sub-Skills in the task — the Work's Skills load as a whole. But remember: the Agent won't automatically call the Skills. You need to tell the Agent what to do.

Recommended approach: Create different sessions within a Project for different tasks. For example, with Amazon Operations Work: one session for competitor check, one for review analysis, one for listing writing. Each session does one thing. The Agent calls the corresponding Skill based on your instructions. Earlier sessions write data to the table. Later sessions (like the weekly report) read from the table to aggregate.

Work Management Rules

As a user, you don't need to memorize many rules. But a few key points are worth knowing:

RuleDescription
Work has its own SkillsSkills inside a Work are plugin-level. They don't appear in the main Skills list. You manage them inside the Work
Loads as a whole, can't splitWhen you specify a Work, all enabled Skills inside load together. You can't pick "only Skill A from this Work" in a task
Toggle anytimeYou can disable unneeded Skills inside the Work in User Capability Management. Next load, they won't come
Version updates are full snapshotsWhen a Work is updated, all files inside are replaced as one snapshot. You can't update just one Skill
One task can use both Skill and WorkYour everyday general Skills are always there. Specifying a Work adds a role capability layer on top

When to Use Skill vs. When to Use Work

ScenarioRecommendationReason
Translate this paragraph for meSkillSingle task, general capability is enough
Summarize these meeting minutesSkillSingle task
Check if competitors changed prices todayWorkNeeds competitor monitoring + data comparison + table write
Write and launch the new listing in three languagesWorkNeeds keyword research + listing optimization + multi-language generation
Generate this week's Amazon operations reportWorkNeeds to aggregate competitor, review, ad, and sales data from multiple sources
Write a follow-up emailSkillSingle task
Rule of thumb: If a task needs only one capability, use a Skill. If it needs multiple capabilities working together as a job workflow, use a Work.

Summary

What's your role? What are the daily tasks that chain together? Package them into a Work, and you have a dedicated tool kit you can pick up and go.
