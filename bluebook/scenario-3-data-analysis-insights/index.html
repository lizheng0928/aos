2.3 Data Analysis & Insights

You have sales data, inventory data, and supplier cost data, scattered across different Base. Field names don't match, formats differ, languages differ. A regular AI assistant typically requires you to upload Excel files manually and analyze one source at a time. AOS Work can connect multiple data sources from Base simultaneously — it auto-cleans data, maps fields, and runs cross-source analysis.

Skills involved: data-cleaning — cleans messy data into analysis-ready tables; analysis-methodology — provides reusable methods for retail analysis scenarios

Steps:

1.

Make sure data sources are in Base (sales table, inventory table, supplier table, etc.)

2.

Tell the Agent what to analyze and which tables to pull from

3.

The Agent auto-queries multiple tables and identifies field mappings

4.

Merges data and runs analysis (trends, rankings, anomalies, margin, etc.)

5.

Results are written back to the Base or formatted as an analysis report

Example prompt:

From the "E-commerce Sales" table and the "Inventory" table, use sell-in, sell-out data to calculate the sell-through rate by SKU in Italy. Rank SKUs by sell-through ascending and write to a "Sell-Through Analysis" Base. Also generate a brief analysis report identifying the 10 slowest-selling SKUs and possible reasons.

Expected results:

•

Sell-through analysis written to the Base, sorted ascending

•

The slowest-selling SKUs in Italy are clearly listed

•

Analysis report identifies the 10 slowest-selling SKUs with possible reasons

•

Later, you can ask the Agent to drill into any SKU's details

Advanced: Multi-Source Data Cleaning

If you have multiple data sources from different systems — SAP sales CSV, Magento e-commerce Excel, supplier quotes in Italian — field names don't match, formats differ, languages differ. Just aligning the fields takes half a day.

With AOS Work, you hand all the data to the Agent. AI auto-identifies field mappings, cleans the data, merges it into one unified table, and gives you a clean data foundation for analysis.

Steps:

1.

Upload each dataset to a Base

2.

Tell the Agent what each dataset is and ask it to auto-identify field mappings

3.

The AI shows you the field mappings (e.g. SAP's "Product Code" = supplier's "Codice"), you confirm

4.

The AI runs data cleaning: deduplication, date format unification, currency normalization, missing value annotation, anomaly detection

5.

The cleaned, merged data is written back to the Base, ready for analysis

Example prompt:

Here are three datasets: SAP store sales (fields in English: Store_ID, Product Code, Revenue, Date), Magento online orders (fields in English: Product Code, Total order, Discount, Revenue), and supplier product costs (fields in Italian: Codice, Prezzo, Categoria). Auto-identify field mappings between these datasets — fields that mean the same thing but have different names — and show me the mapping for confirmation. After confirmation, clean the merged data: 1) Deduplicate and mark duplicate records; 2) Unify dates to YYYY-MM-DD, amounts to EUR; 3) Mark missing values and suggest how to handle them; 4) Detect anomalies and flag them. Write the cleaned merged data back to a Base.

Expected results:

•

Field mapping inventory: AI auto-identifies field mappings across the three datasets

•

Cleaned merged table: deduplicated, format-normalized, missing values annotated, anomalies flagged

•

Data quality report: number of duplicate records, missing value distribution, anomaly list

•

Merged data written back to the Base — ready for analysis without re-cleaning

Data cleaning is the prerequisite for analysis. Let AI handle the alignment and cleaning. You just confirm the mappings and rules. Want to know what to do with the cleaned data? → See 3.8: "Merchandise Planning: Product Operations Analysis & Inventory Risk Alerts."
